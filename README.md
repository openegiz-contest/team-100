## Стенд «Актогай»: запуск и проверка

### Как проверить за 5 минут

Стенд работает сам (запуск — ниже, «Запуск с чистой Ubuntu 24.04»); нажимать ничего не нужно. Адреса — от `http://localhost:8000/`, без логина.
Если браузера с JavaScript под рукой нет (curl, текстовый браузер): `http://localhost:8000/summary` — то же состояние текстом, собранное на сервере из данных двойника (время модели, беда № 1 с ценой и «кого звать», очередь, плитки, модули, сценарии с адресами запуска и ожидаемым итогом, список всех страниц); `http://localhost:8000/summary.json` — те же данные, `/api/state` — все вещи двойника.

| Минута | Что сделать | Что увидеть |
|---|---|---|
| 0:00 | открыть `/` | часы модели идут (минута = час; смена 08:00–20:00 проходит за 12 минут), сверху одна строка «что сейчас и что делать»; если бед нет, в ней кнопка **«Показать пример смены»**: запускает сценарий «Две беды сразу» с 08:00 (seed 42) |
| 0:30 | `?view=queue` («Все беды») | порядок вызова по деньгам; у каждой беды цена, кого звать, «Подробнее»: из чего цена, измерения и возраст данных, цена часа задержки вызова по опыту |
| 1:30 | `?view=copper`, `?view=inside` | «Путь меди» (потоки, балансы, окисленная ветка); «Изнутри» (узлы, сигналы, источники) |
| 2:30 | `?view=economics`, `?view=calib` | +0,61 т Cu за смену [95 % ДИ +0,23; +2,18] на симметричной базе (медиана +0,09, без смены-выброса +0,26), оба края допущения о твёрдой руде и обе трактовки склада, прежний результат как история, CO₂; калибровка, где извлечение 2024 г. вне допуска показано как есть, и сверка с фактом KAZ Minerals |
| 3:30 | `?view=howto` | таблица «утверждение → где посмотреть → источник»; «Ожидаемый итог сценариев» (посчитан заранее тем же кодом, seed 42, оценка на модели) с живой сверкой; реестр чисел «Откуда числа» (у каждого числа — опыт и способ проверки); живой статус модулей; свёртка лавины тревог в одну беду |
| 4:00 | `?view=modules` («Анализ» → «Модули») | что читает и что решает каждый модуль, последнее решение со временем модели, отставание от симулятора; «Эффект модуля в один клик»: «Две беды сразу» и счётчик «с двойником сейчас +X т Cu против копии без двойника»; проверка «Где теряется медь» на 600 прогонах скрытых причин: доля найденных, задержка, ложные тревоги, и проверка датчиков и детектора на открытых данных флотации железной руды (`VALIDATION.md` 8.18) |
| 4:30 | `python3 -I aktogay/scripts/check_numbers.py` и `make akt-check` | «ok / FAIL + доказательство» по каждой строке за ≈ 15 с |

Тесты: `python3 -I -m unittest discover -s aktogay/tests -t aktogay` (1032 теста; Windows 11, 25.10.2026 — 7 мин, все ok; на Ubuntu 24.04 в контейнере 24.10.2026 было 982 теста — 5 мин 14 с, все ok, 37 тестов страниц под node пропущены: в чистой Ubuntu node нет). ### Достоверность одним взглядом

- **Проверено на данных, которых модель не видела:** медь в концентрате по 28 кварталам 2018–2024 (средняя ошибка около 2,3 %) и вперёд на I–II кв. 2026 г.; вода 2023 г.; пять перефутеровок SAG (тест слабый); шум датчиков и ложные тревоги — на открытом наборе железной руды.
- **Подогнано, не проверка:** готовность линии, энергия SAG и предельное извлечение на 2025 г.; «прочая» нагрузка и испарение на 2024 г.; кинетика кучи окисленной ветки.
- **Не доказано:** формула извлечения по содержанию не лучше константы 87,2 % (2024 г. вне допуска); выигрыш двойника — оценка на модели; датчики стенда синтетические. Из 812 чисел 570 — допущения, но вывод двигают только 30, из них допущений 19 (VALIDATION 9.4).
- Сводная таблица «механизм → данные → период вне подгонки → метрика → допуск → эталон → результат» — в начале раздела 1 `VALIDATION.md`.

Что сверено с реальными данными и насколько близко. Модель подогнана на 2025 г.; в таблице то, что в подгонке не участвовало. Подробности и источники — `VALIDATION.md` (раздел в последней колонке); то же текстом и с живым счётом проверки правдоподобия — `http://localhost:8000/summary`.

**Из чего складывается польза.** Польза = сэкономленные часы промедления × цена часа: цена часа простоя линии сверена с реальными перефутеровками Актогая [факт, VALIDATION 6.3, 6.8]; сэкономленные часы — оценка на модели по опубликованным задержкам людей [VALIDATION 8.17]; механизм подтверждает и KAZ Minerals: рост переработки 2025 г. — «reduced maintenance downtime» (сокращение простоев на обслуживании) [факт, Q4 2025, с. 3].

Пределы: выигрыш двойника (+0,61 т Cu за смену [95 % ДИ +0,23; +2,18], 100 парных смен) получен на модели против модели, на фабрике не проверен; формула извлечения не лучше константы 87,2 % (ошибка около 1,8 п.п. против 1,40 п.п. по 28 кварталам); вне допуска два числа — извлечение 2024 г. (−0,68 п.п.) и извлечение III кв. 2025 г., промах не подгоняли.

### О стенде

Цифровой двойник сульфидной части Актогая (KAZ Minerals): карьер, две линии фабрики, концентрат,
вода, энергия и люди смены. Стенд — платформа OpenEgiz v1.0.4 и оверлей `aktogay/compose.yml`
(сервисы `akt-models`, `akt-setup`, `akt-calib`, `akt-sim`, `akt-modules`, `akt-web`). В платформе
изменён только `Makefile`: строка `COMPOSE` подключает оверлей, в `up` добавлены проверка портов
8000 и 8092, ожидание `akt-setup` и печать адресов стенда, добавлены цели `akt-check` и `akt-calib`.
Что и зачем моделируем — `SUBMISSION.md`.

### Требования

- Ubuntu 24.04 (или Windows 11 с WSL2 и Ubuntu 24.04 — `OPENEGIZ.ru.md`, раздел «Windows (WSL2)»).
- Docker Engine с Compose v2.20+ (`docker version`, `docker compose version`), `git`, `make`, `curl` (для `make akt-check`).
- Память для Docker: шаблон рекомендует 6 ГБ. Работающий стенд занимает ≈ 3,5 ГиБ (замер
  22.10.2026: 17 контейнеров, 3,48 ГиБ; из них сервисы `akt-*` — около 0,1 ГиБ). При 5–6 ГБ
  `make up` печатает WARNING — это не ошибка.
- Сеть при первом запуске: Docker Hub (образы платформы, `python:3.12.11-slim-bookworm`,
  `node:20-slim`, `nginx:1.25-alpine`), GitHub (исходники extended API Ditto), npm (`yarn install`),
  PyPI (`paho-mqtt==2.1.0` в образе симулятора).
- Браузер для 3D: вид «3D» (диорама и «Спутник 3D») требует WebGL — видеокарту или Chrome с флагом
  `--enable-unsafe-swiftshader` (программный WebGL; он занимает процессор, см. «Если что-то не так»). Для платформы,
  модели и всех экранов, кроме 3D, видеокарта не нужна: без WebGL все данные и последствия сценариев показаны на 2D-плане.

### Запуск с чистой Ubuntu 24.04

Все команды — из корня репозитория.

```bash
git clone https://github.com/openegiz-contest/team-100.git && cd team-100   # если репозиторий ещё не склонирован
sudo apt-get update && sudo apt-get install -y make   # в чистой Ubuntu make нет; меньше минуты
make up            # платформа + стенд; в конце печатает адреса и пароли
make akt-check     # «ok / FAIL + доказательство» по каждой строке; ≈ 15 с
make akt-calib     # таблица калибровки в терминале; 2–4 мин (те же числа уже в меню «Калибровка»)
```

Если `make up` падает с `permission denied ... /var/run/docker.sock`, пользователь не в группе
`docker`: `sudo usermod -aG docker $USER`, выйти из сеанса, войти снова и повторить `make up`.
Сбои сети при сборке (например, обрыв выдачи исходников с GitHub: `early EOF`, `RPC failed`) `make up` повторяет сам, до трёх раз; если сборка всё же не прошла, повторите `make up` — скачанное остаётся в кеше.

Что делает `make up` (порядок рецепта): создаёт `deploy/compose/.env` с новыми паролями, проверяет
порты и память (`scripts/compose-preflight.sh`, `aktogay/scripts/akt-preflight.sh`), собирает и
поднимает контейнеры (`up -d --build --wait`), ждёт завершения разовых задач `init` и `akt-setup`
(политика, модели типов, 141 постоянная вещь), ждёт, пока Ditto стабильно отвечает, и печатает
адреса. Повторный `make up` ничего не дублирует: `akt-setup` создаёт только недостающие вещи.

### Повторить опыт «вкл/выкл» одной командой

100 парных смен (seed 1001–1100) с 2–3 бедами: копии «двойник, порядок по $», «двойник, порядок по
громкости», «как сейчас» (без двойника) и «база». Печатает средние с 95 % ДИ (бутстрэп BCa), доли
смен без разницы и хуже базы с интервалами Уилсона, тест Уилкоксона и срезы. Нужен Python 3.11+
(в Ubuntu 24.04 есть `python3` 3.12), только стандартная библиотека:

```bash
python3 -I -B aktogay/run.py trial --n 100 --seed0 1001 --no-twin --library tier_s --jobs 3 --out trial.json
```

Это главный опыт 24.10.2026 на симметричной базе (по умолчанию `--twin-human same`). Прежнюю базу, на которой двойник видит громкую беду в её первую минуту, возвращает `--twin-human none`; другой край допущения о твёрдой руде — `--asis-hard sag`.

≈ 5–10 мин (4 процесса; 22.10.2026: 219 с без уровня S — поле `seconds` в `aktogay/sim/data/trial_n100.json`). Те же seed дают те же числа: повтор на коде
22.10.2026 совпал во всех статистиках с `aktogay/sim/data/trial_n100.json`, который показывает меню
«Калибровка» в разделе о прежнем опыте: двойник против «как сейчас» +1,26 т Cu за смену с бедами [95 % ДИ +1,06; +1,52]
(опыт 22.10.2026, библиотека бед без уровня S; историческая запись) [оценка на модели]. Главный результат — опыт
24.10.2026 с полной библиотекой бед на симметричной базе: двойник − «как сейчас» **+0,61 т Cu за смену [+0,23; +2,18]**, медиана +0,09, без одной смены-выброса +0,26 [+0,18; +0,35], 1 % смен хуже (повтор на seed 2001–2100: +0,31 [+0,21; +0,47]); если твёрдая руда «как сейчас» узнана только на SAG — +1,19 [+0,77; +2,81] и +0,81 [+0,58; +1,14]; на тонну меди −28 кВт·ч энергии. Прежний результат (+1,07 [+0,89; +1,31], двойник видел громкую беду в первую минуту) сохранён как история.
Данные — `aktogay/sim/data/experiment_24.json` (сводка `python3 -I -B aktogay/run.py exp24 --write aktogay/sim/data/experiment_24.json` по прогонам `aktogay/sim/data/exp24/`) и `experiment_23.json` (прежняя база); меню «Экономика» и «Калибровка» читают `exp23.json`, собранный из обоих (`python3 -I -B aktogay/run.py exp23 --write aktogay/web/static/exp23.json`) [оценка на модели]. Последние строки вывода — сводка; весь результат — в `trial.json`.
Без Python на хосте — тот же расчёт в образе, который уже скачан для `akt-setup`:

```bash
docker run --rm -v "$PWD/aktogay:/akt:ro" -v "$PWD:/out" docker.io/library/python:3.12.11-slim-bookworm \
  python -I -B /akt/run.py trial --n 100 --seed0 1001 --no-twin --library tier_s --jobs 3 --out /out/trial.json
```

Ключи для чувствительности: `--set sens_lab_delay_h=0` или `=4` (лаборатория отвечает через 2 или
6 ч вместо 4), `--kip 2` (два дежурных КИПиА), `--sigma-ln 0.7` (разброс ремонта), `--miss 0.3`
(двойник пропускает 30 % тихих бед), `--detect-min 120` (находит позже), `--hidden-mult 2` (тихих
бед вдвое больше), `--asis-notice 30` (смена без двойника решает через 30 мин), `--twin-human none` (прежняя база: двойник видит громкую беду сразу), `--asis-hard sag` (твёрдую руду «как сейчас» узнают на SAG), `--price 10000`
(цена меди, $/т), `--no-asis` (старая база, где без двойника решений не принимает никто).

| `Ports already in use: AKT_WEB_PORT=8000` (или `AKT_MODELS_PORT=8092`, или порт платформы) | порт занят чужой программой: остановить её или задать другой порт в `deploy/compose/.env` (например `AKT_WEB_PORT=8001`) и снова `make up` |
| WARNING про память Docker | стенд работает и при 5 ГиБ для Docker; при постоянных перезапусках контейнеров дать Docker 6 ГБ |
| `ERROR: the akt-setup job ... failed` | `make logs S=akt-setup`; обычно Ditto ещё не поднялся — повторить `make up` (повтор безопасен) |
| `make up` падает на сборке (`failed to solve`, `yarn`, `pip`) | нет доступа к Docker Hub, GitHub, npm или PyPI; проверить сеть и повторить `make up` |
| На панели «ПРОГРЕВ» | идёт прогрев 06:00 → 08:00 нового прогона, ≈ 15 с |
| На панели «ПАУЗА», часы стоят на 20:00 | автопауза в конце смены сценария: «Сбросить 08:00» или кнопка ×60 |
| «Калибровка» пишет, что калибровка считается | `akt-calib` ещё считает (2–5 мин после `make up`); `make logs S=akt-calib`; можно запустить `make akt-calib` |
| На видах «3D», «Диорама» и «Спутник 3D» — 2D-план и пояснение «3D требует WebGL…» | в браузере нет WebGL: включить аппаратное ускорение или запустить Chrome с флагом `--enable-unsafe-swiftshader`; данные и последствия сценариев при этом видны на 2D-плане |
| `make akt-check`: FAIL у `mod-*` | модули ещё не прошли такт нового прогона; повторить через минуту; `make logs S=akt-modules` |
| Всё остальное | `make ps`, `make logs S=<сервис>`; с чистого листа — `make clean && make up` (удаляет данные и пароли) |

`make example-mine` на этом стенде не запускать: он создаёт маркер `deploy/compose/.example-mine`,
и каждый следующий `make up` поднимает ещё и симулятор примера рудника. Убрать — `make clean`.
