# «Диорама»: договор модулей-строителей

Вид `?view=diorama` (пункт меню «Диорама») — весь рудник Актогай как макет на
подиуме: карьер, ЦПД, склады руды, две линии фабрики, склад концентрата и
ж/д, хвостохранилище, вода, энергия, люди смены. Схема, не масштаб: машины и
здания крупнее масштаба, глубина карьера 230 м — факт (`pit.passport.depth_m`).
Всё живое берётся из Ditto через уже работающий опрос `/api/state` в `app.js`
(раз в 2 с); модули сами в сеть не ходят (п. 6.2: только Ditto и InfluxDB).

| Файл | Что делает |
|---|---|
| `core.js` | ядро: подиум со срезом пород, свет, камера и пресеты «Весь рудник / Карьер / Фабрика / Хвосты», мышь и пальцы, слой HTML-подписей без наложений, свечение бед и пути до меди, клик — карточка, заготовки для вещей без модели, счётчики скорости, переход на 2D-план без WebGL |
| `layout.js` | расстановка: подиум, карьер, зоны, узлы (`NODES`), линии схемы (`LINES`), место любой вещи Ditto |
| `pit.js` | карьер (уступы, спиральный съезд), отвал вскрыши, дороги и кривые рейсов самосвалов; строит ядро |
| `mining.js` | модуль «горные работы» |
| `plant.js` | модуль «фабрика» |
| `infra.js` | модуль «инфраструктура» |

Порядок запуска: подиум и площадки → `pit.js` → модули (загрузка параллельно,
`build` по очереди: mining, plant, infra) → подписи зон и бед → заготовки для
вещей, которые никто не занял → первый кадр. Ошибка в `build` или `update`
одного модуля выключает только его (сообщение в строке под кнопками камеры),
остальная сцена работает.

## Модуль

```js
export function build(ctx) {            // можно async
  // меши, подписи, клики — один раз
  return {
    update(state, dt) { /* каждый кадр */ },
    destroy() { /* своё, чего нет в ctx.keep */ },
  };                                     // или null: обновлять нечего
}
```

* `update(state, dt)` вызывается каждый кадр (не чаще ≈ 30 раз в секунду),
  `dt` — секунды с прошлого кадра (≤ 0,1).
* `state.fresh === true` ровно в одном кадре после каждого опроса Ditto: тогда
  читать `ctx.AKT` и менять цели (состояние, место, уровни, скорости). В
  остальных кадрах — только анимация к целям (интерполяция, бег текстур).
* При паузе модели (`state.paused`) движение машин, лент и мельниц стоит;
  свечение и подписи остаются.
* Ничего не создавать в `update` (геометрии, материалы, векторы в цикле) —
  всё заранее в `build`.

## Координаты и layout

Условные единицы подиума (у.е.): `x` — вправо, `z` — к зрителю, `y` — вверх,
верх подиума `y = 0`. Подиум 1500 × 1000 у.е., толщина 150 + подставка 24.
Карьер: центр (−430, −10), бровка — эллипс 270 × 240 с неровностью
(`pitR(θ)`), 8 уступов схемы, `levelY(L) = −15·L`, дно −120 у.е. = 230 м.

`ctx.layout`:

| Метод | Что даёт |
|---|---|
| `pos(id)` | точка на земле, где стоит вещь (копия `Vector3`): узел из `NODES`, забой, дорога (середина кривой), место по `location / node / task …`, родитель, иначе полка «прочее» |
| `top(id, lift)` | точка над вещью для подписи (верх узла + `lift`) |
| `stand(id)` | где стоит человек у узла (`NODES[id].at` или перед узлом) |
| `around(id, i, n, step)` | i-е из n мест вокруг узла (спираль) |
| `face(id)` | забой: `{level, angle, s, y, pos (середина бермы), wall (подошва откоса), out, tangent}` |
| `excFace(exc)` | забой экскаватора (`face.passport.excavator`) |
| `node(id)`, `zone(k)`, `zoneOf(id)` | узел (`x, z, w, d, h, r, zone, at`), зона (`x0..x1, z0..z1` или `x, z, r`), зона узла |
| `line(k)` | точки линии схемы `LINES[k]` на земле |
| `groundAt(x, z)` | рельеф без площадок и без выемки съезда (для зданий лучше `ctx.heightAt`) |

`NODES` (центр, размер площадки, высота для подписи): `pit`, `dump`, `fleet`
(ремонтный бокс), `abk`, `crusher-1/2`, `conveyor-1/2`, `stockpile-1/2`,
`weigher-1/2`, `line-1/2`, `sag-N`, `pebble-N`, `ball-Na/b`, `cyclones-N`,
`flot-N`, `rougher-N`, `cleaner-N`, `analyzer-N`, `flowmeter-N`, `thick-N`,
`filter-N`, `conc-stock`, `rail`, `power`, `water` (хвостохранилище),
`water-tank`, `piezo-1/2/3`. Линия 2 — та же раскладка со сдвигом +245 по `z`.

`PolyCurve` (наследник `THREE.Curve`, параметр по длине): `getPointAt(u)`,
`getTangentAt(u)`, `len`, `at(d)` (точка на расстоянии `d` у.е., `d < 0` — от конца).

Вещь, которую никто не занял (`claim` / `onClick`), ядро показывает

вещей. Модуль, который рисует вещь, обязан её занять.

## Свечение

* Беда в очереди — красное свечение узла, пульсирует; состояние «стоит»
  (`AKT.stopped`) — красное ровное; путь беды до меди (`state.chain`) — синее;
  выбранный в панели узел — светлый.
* Меши, отданные в `onClick(id, mesh)` с `halo` по умолчанию, ядро подсвечивает
  само: подменяет материал на копию с `emissive` (для `MeshBasicMaterial` —
  оттенок). Один меш — одна вещь. Если модуль сам сменил `mesh.material`, ядро
  возьмёт его за основу на следующем опросе.
* Экземпляры `InstancedMesh` модуль красит сам: `ctx.glowOf(id)` →
  `ctx.glowColors[...]` в цвет экземпляра.
* «Работает» — свои светящиеся части (`materials.lampRun`, `ctx.mat(hex, {emissive})`),
  не свечение ядра.

## Подписи

`ctx.label(key, text, o)` → `{el, set(text), setAt(v), setTitle(t), hide(bool), remove()}`.

* `key` — уникальный; модулю — свой префикс (`mining:truck-01`). Ключи ядра:
  `issue:*`, `zone:*`, `ghost:*`, `plate`; `pit.js` — `pit`, `dump`, `road:*`.
* `text` — строка или функция (вызывается после каждого опроса); `''` — скрыть;
  `'\n'` — вторая строка мелким шрифтом (для «оценка на модели», «допущение»).
* `o.thing` — вещь (цвет состояния, свечение, ссылка на карточку; люди и
  бригады открывают карточку человека); по умолчанию — `key`, если это вещь.
* `o.at` — `Vector3` или функция (для движущихся); по умолчанию `layout.top(thing)`; `o.lift`.
* `o.prio`: 0 — всегда видна (беды); 1 — линии; 2 — главные узлы (дробилки,
  склады, концентрат, вода, энергия); 3 — переделы фабрики; 4 — экскаваторы;
  5 — люди; 6–7 — машины и приборы; 8–9 — надписи зон. Меньше — важнее,
  подписи с большим числом уступают место.
* `o.maxDist` / `o.minDist` — показывать только ближе / дальше (у.е. до цели
  камеры; «Весь рудник» ≈ 2 700, «Карьер», «Фабрика» ≈ 1 200).
* `o.kind`: `''`, `small`, `zone`, `plate`, `issue`; `o.title` — подсказка; `o.href`.
* Числа — только HTML-текстом, как пришли из Ditto (`AKT.fmt`, с единицей).
  Расчёт модулей (`mod-*`, деньги, потери) — с «оценка на модели» (`AKT.EST`),
  допущения стенда — с «допущение» (`AKT.ASSUME`). Размеры и места на макете
  — схема, чисел о них не писать.
* Норма не привлекает взгляд (ISA-101): у самосвалов, бульдозеров, станков,
  забоев и приборов подпись — только при отклонении (`AKT.deviates`); машины —
  бортовым номером (`AKT.shortName`: HT225, EX01, DZ21, DR31).

## Скорость

Цель: в headless Chrome на SwiftShader при 1280 × 720 — не меньше 15 кадров/с,
сцена готова < 5 с после ответа `/api/state`; всего < 300 вызовов отрисовки.

| Часть | Вызовов отрисовки | Треугольников |
|---|---|---|
| ядро и `pit.js` (сейчас) | 14 | 16,6 тыс. |
| `mining.js` | ≤ 100 | ≤ 60 тыс. |
| `plant.js` | ≤ 110 | ≤ 50 тыс. |
| `infra.js` | ≤ 60 | ≤ 20 тыс. |

* Программный WebGL упирается в пиксели: большие поверхности (здания, кровли,
  пруд, площадки) — `ctx.merge` + `ctx.bake` → `materials.baked` (в разы
  дешевле Ламберта на пиксель). Ламберт — для мелких и движущихся частей.
* Одинаковые машины — `InstancedMesh` на каждую часть (кузов, кабина, колёса),
  не меш на машину. Карт теней нет; тени — `ctx.blob`.
* Прозрачное — только где нужно (пена, вода), без `depthWrite`.
* Без WebGL, при потере контекста или ошибке ядра вид сам переходит на 2D-план
  с пояснением.
* При «кадр/с» ниже 18 ядро само снижает разрешение холста (до 0,6).

## Проверка

* `?view=diorama&perf=1` — под кнопками: кадров в секунду (и запас), цена кадра
  с растеризацией, вызовы отрисовки, треугольники; `window.__dio` — то же
  объектом (`fps`, `fpsEq`, `fullMs`, `calls`, `tris`, `marks` — шаги загрузки, мс);
  `window.__dioDebug` — `pick(x, y)` (вещь под пикселем), `screen(x, y, z)`
  (точка подиума на экране), `route(a, b)`, `path(name)` (длины в у.е.).
* `?cam=all|pit|plant|tails` — пресет камеры; `?focus=<вещь>` — камера к вещи;
  `?q=0.6` — плотность пикселей холста вручную.
