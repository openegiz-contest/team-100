# akt-web: интерфейс стенда «Актогай»

Небольшой бэкенд на стандартной библиотеке Python 3.12 (`server.py`) и
статические страницы (`static/`); единственная библиотека — three.js r160 для видов «Диорама» и «Спутник 3D», лежит в
`static/vendor/three-0.160.0/` (MIT, `LICENSE.txt`), из сети ничего не грузится. Контейнер `akt-web`
в `aktogay/compose.yml`, порт `127.0.0.1:8000`, без логина.

Правила (п. 6.2 положения): интерфейс читает только Ditto (состояние вещей,
опрос раз в 2 с) и InfluxDB (тренды, журнал), пишет только в вещи `control`
и `journal` (merge-patch на `/features`, заголовок `x-correlation-id`
`akt-web-<вещь>`). Симулятор ему недоступен. Пароли Ditto и токен InfluxDB
живут только в процессе `server.py`.

## Виды (`?view=…`)

| Вид | Что показывает |
|---|---|
| `site` (меню «Спутник 3D») | three.js r160 (`static/vendor/three-0.160.0/`, MIT, файл лицензии рядом; грузится только на этом виде): земля — снимок Sentinel-2, карьер — террасный конус по контуру OSM глубиной 230 м (факт, уступы — схема), корпуса, склады (конус ∝ запасу), ленты (бег текстуры ∝ т/ч), хвостохранилище, ЛЭП, экскаваторы; самосвалы — вещи `truck` из Ditto, если есть, иначе «схема движения по данным парка» (`fleet.trucks_ready`, `haul_tph`); люди, датчики, пьезометры и прочие новые вещи — по координатам (`AKT.pos`). Числа — HTML-подписи над сценой без наложений; клик — карточка; камеры «Площадка / Карьер / Фабрика»; без теней, работает на программном WebGL. Нет WebGL или сцена не запустилась — показывается 2D-план с пояснением |
| `diorama` (меню «Диорама», главный 3D-вид; `view=3d` — то же) | весь рудник как макет на подиуме (`static/diorama/`, three.js r160 из `vendor/`): карьер с уступами и спиральным съездом (глубина 230 м — факт, уступы — схема), отвал, дороги, площадки ЦПД, складов, фабрики, хвостохранилища, подстанции; срез подиума — породы по глубине (схема). Машины, переделы фабрики, вода, энергия и люди — модули `mining.js`, `plant.js`, `infra.js` по договору `static/diorama/API.md`; вещь Ditto без подробной модели видна полупрозрачным блоком на своём месте. Беда в очереди светится красным, путь беды по `feeds` до склада концентрата — синим. Числа — HTML-подписи без наложений, с выносками; клик — карточка (люди — карточка человека); камеры «Весь рудник / Карьер / Фабрика / Хвосты» (`cam=`), `focus=<вещь>`, `perf=1` — счётчики скорости. Свет запечён в цвета вершин, теней нет — работает на программном WebGL (SwiftShader); без WebGL — 2D-план с пояснением. Подпись «схема, машины крупнее масштаба» и под ней свежесть данных техники карьера: «обновляются по очереди, каждая машина — раз в ~N мин модели · обновлено M с назад» (N — разброс `sim_time` техники, M — `_modified` самой свежей), между обновлениями движение — схема. Мелкие узлы фабрики (шаровые, основная и перечистная флотация) подписаны только при отклонении; объём пруда помечен «(д)» — допущение, регулятор держит его почти постоянным. Проверка 22.10.2026 при 1280×720: на всех четырёх камерах — до 24 видимых подписей, 0 наложений, 0 обрезанных, ни одна не заходит под строку свежести |
| `plan` (по умолчанию) | 2D-план, подложка «Схема / Спутник» (снимок `static/sat/aktogay_s2.jpg`, рамка из `sat/aktogay_s2.json`, подпись «Contains modified Copernicus Sentinel data 2026»); короткие подписи, подробности во всплывающей подсказке и в карточке; новые типы вещей (люди, датчики, пьезометры, самосвалы, забои, дороги, беды с водой, HPGR) рисуются значками по координатам из Ditto; 2D-план площадки из выгрузки OSM (`static/plan.json`), ленты шириной ∝ т/ч, склады с уровнем, партии руды, номера бед, бригады, врезка «Фабрика»; легенда знаков над планом; «© OpenStreetMap contributors, ODbL», линейка 1 км, стрелка «С». Подписи, значки и слои складов — в пиксельных группах; после каждого опроса раскладка (`layout()` в `plan.js`) сдвигает их так, чтобы ни один текст не лёг на другой и не вышел за край (при 1280×720: 0 пар, 0 обрезанных), выноски идут за подписью |
| `line1`, `line2` (`line&n=`) | SVG-схема линии из `feeds` и `ui.scheme`: склад → SAG ⇄ галя → шаровые ⇄ циклоны → рамка «Флотация» → сгуститель → фильтр → склад концентрата; полоски «значение / предел»; тренды хвостов (с уставкой АСУ) и извлечения |
| `unit&id=kz.aktogay:sag-1` (`card`) | паспорт с источниками и метками, признаки, «данные из Ditto, обновлено N с назад», тренд 2 ч, сырой JSON вещи, «Кто отвечает», «Позвать» |
| `queue` | очередь бед целиком, тексты модуля akt-priority, журнал; «ждём к ЧЧ:ММ» и «не прибыл» с кнопками «Напомнить» / «Позвать следующего» (`POST /api/remind`); раздел «Тихие перерасходы» (`mod-losses.silent_text`: энергия SAG, собиратель, вода) и лист сдачи смены; в журнале — строки модуля «двойник: не прибыл / прибыли» |
| `handover` (меню «Ещё → Сдача смены») | лист сдачи смены `mod-priority.handover` (07:30 и 19:30 модели) и «если сдавать сейчас» (`handover_draft_text`); подпись — Plocher и др. 2011 [литература] |
| `ore` | партии, прогноз akt-ore на 12 ч, слои складов, «сбылось ли» |
| `calib` | из `validation-calib.report_json` (пишет разовый контейнер akt-calib): проверка «очередь по $ против очереди по громкости» на 100 парных сменах (средние с ДИ BCa, p0 и p− с интервалами Уилсона, вклад обнаружения, срезы) и таблица калибровки «модель / отчёт / отклонение / допуск»; балансы и мощность по частям из `mod-losses`, итог смены и копии из `baseline` |
| `tree` | дерево вещей по `_parents` |
| `text` | всё текстом, для печати и экранных чтецов |
| `legend` | почему серый, что значат цвета, руда, знаки, метки чисел |

Над всеми видами — строка «что это и что делать» (`AKT.nowLine()` в `app.js`): время модели, ход, учебный
сценарий и одно предложение о главной беде с одной ценой («час промедления ≈ $X» или «позвать до ЧЧ:ММ») и
кнопкой «Позвать …». Панель справа: 6 чисел (теряем сейчас, медь, руда, извлечение, сеть, стоимость меди —
с дельтой за час и спарклайном из InfluxDB), карточка беды ① (сколько теряем, час промедления, кого звать,
почему; «Позвать …» и «Не сейчас…» — форма причины в строке, без системных окон), беды ②③ строкой, люди
(вызванные полностью, свободные одной строкой), «Где теряем медь» (только потери больше точности,
«точность низкая», когда ошибка больше значения), журнал смены и свёрнутый «Пульт модели» (скорость, учебные
сценарии с описанием «что случится / за чем следить / как отменить» и подтверждением, «Начать смену заново»
с номером прогона, «Режим проверки модели»). Пока идёт сценарий, сверху панели — баннер с обратным отсчётом и
«Остановить сценарий…». `help.js`: словарь (≈ 40 терминов, подсказки на `.term`), тур «Как пользоваться»
(5 шагов, `?tour=1`), «Спросить двойник» (11 вопросов, в том числе «Что передать смене?» — по листу сдачи диспетчера и свой вопрос по ключевым словам; ответы —
шаблоны над живыми данными, без сети и языковой модели; `?ask=<id>`). План: слои «Техника / Люди / Руда /
Вода и энергия / Датчики» (выбор в `localStorage` `akt-layers`), подписи только у главных узлов и отклонений,
сводка «в ремонте: …» вместо значков, у беды ① пульсирующее кольцо уровня и выноска с ценой; самосвалы
движутся по дорогам карьера, руда — по лентам со скоростью ∝ т/ч (один `requestAnimationFrame`, стоит на
паузе модели и в скрытой вкладке). Параметры адреса: `scenario=crusher:1|grid|hard:1|reline:1|water|hpgr_fire`,
`layer=sat|scheme`, `preset=fork`, `kip=1|2`, `safety=1`, `auto=0|1`, `speed=60|300|1200`, `run=1`
(срабатывает один раз), `sim=1` (открыть «Пульт модели»), `check=1`.

Все суммы в $, потери, прогнозы, слои склада и итоги копий — со знаком «≈» (расчёт модели, одна строка
в легенде); числа без источника — «(д)» (допущение); остальное измерено (пришло из Ditto).

Во время сценария главные числа на плане и схеме линии показаны парой
«база → сейчас» («3 850 → 0 т/ч» у дробилки, «3 886 → 1 931» у линии): база —
признак `baseline.<вещь>_<признак>_base` копии без сценария; пара видна, когда
вещь `baseline` из того же прогона и числа расходятся больше чем на 2 %.
«Итог смены» берётся из `baseline.shift_result`, только если в нём `run` текущего
прогона (иначе блок скрыт): фиксированная форма {run, kind, t_min, copies{fact,
base, loud, no_twin}, diff, fork}, поэтому merge в Ditto не оставляет ключей
старого прогона, а интерфейс показывает только эти ключи.

Беда в панели: «идут потери −$X/ч», «потерь пока нет; с 01:23 завтра: −$X/ч»
(`loss_from`) или «S0: … в деньгах не считается». Время с другим днём модели
подписано «завтра» / «вчера».

Английские имена из Ditto (ключи признаков и паспорта, единицы, состояния,
виды бед, ключи объектов) показываются по-русски через `static/ru.js`; состояние
читается по типу вещи (партия DONE — «переработана», калибровка DONE — «готово»).
Партии — только из текущего прогона и не отставшие от остальных больше чем на
30 мин модели (удаление, потерянное Ditto, не оставляет «сирот» на виде «Руда»).

## API

| Запрос | Что делает |
|---|---|
| `GET /healthz` | «процесс жив», в Ditto не ходит |
| `GET /api/state` | все вещи `kz.aktogay:*` (поиск Ditto, `size(200)`, поля с `_modified`), кэш 1 с |
| `GET /api/thing?id=` | сырой JSON одной вещи |
| `GET /api/history?thing=&field=f1,f2&range=2h[&run=]` | точки InfluxDB по `sim_time` (поля `value_<f>_properties_value`) |
| `GET /api/journal?range=24h[&run=]` | строки `journal.last` из InfluxDB (`value_last_properties_value_*`) |
| `POST /api/scenario {id, preset?, kip?, safety?, auto?, speed?}` | `control.scenario` = {seq, id, …, sim_time, run, t_wall} |
| `POST /api/cancel`, `POST /api/reset {seed}`, `POST /api/speed {value: 0/60/300/1200}` | `control.cancel`, `control.reset` = {seq, seed, speed, start}, `control.speed` = {seq, value} |
| `POST /api/call {issue, role, text, via?}` (`via` = `deputy` или `head`, когда основной занят по наряду-допуску), `POST /api/snooze {issue, role, reason}` | `journal.last` = {seq, issue, action: call/snooze, role, text, sim_time, run, t_wall} |
| `POST /api/remind {issue, role, text, next?}` | `journal.last` с action `remind` (напомнить вызванному) или `next` (позвать следующего); akt-sim сокращает дорогу, akt-priority ставит новое ETA |

`seq` растёт на 1 от текущего значения в Ditto; симулятор отбрасывает повтор
с тем же `seq` и `t_wall`. Если Ditto не ответил на чтение текущего значения,
команда не пишется (ответ 502, кнопку можно нажать ещё раз): угаданное «пусто»
начало бы `seq` с 1, а симулятор такие команды раньше отбрасывал до перезапуска
(теперь он принимает и меньший `seq`, если `t_wall` новее). Вместе с объектом в
`control` и `journal` пишутся `idSimulationRun` и `sim_time` площадки, поэтому
строки в InfluxDB несут тег прогона.

## План из OSM

`tools/osm2plan.py ../osm/core.geojson static/plan.json` упрощает выгрузку
Overpass до ≈ 560 точек (Дуглас–Пекер, допуски по слоям), переводит в метры от
точки 79.93° в.д., 46.94° с.ш. и добавляет `anchors` — где на плане стоит каждая
вещь. Объекты, которых в OSM нет (дробилка 2, склады руды, склад концентрата,
экскаваторы, бригады), подписаны «схема». Атрибут `ui.plan = {x, y}` у вещи в
Ditto, если появится, важнее `anchors`. Место вещи нового типа берётся по порядку из признаков
`x`/`y`, `x_m`/`y_m`, `position`, `lat`/`lon`, атрибутов `ui.plan`, `geo`, затем из `anchors` и, наконец,
от вещи, на которую она ссылается (`location`, `at`, `node`, `task` …); линия — из `path` / `ui.path`.
Часть имён в выгрузке OSM пришла как UTF-8, прочитанный в latin-1 («ÐÒÑÐ¾ÒÐ°Ð¹»); `osm2plan.py`
перекодирует их обратно («Ақтоғай»).
